# DividendOS 국내 금융 앱 UX 검토 · 1.13

2026-10-18, 기존 1.12의 실제 화면과 코드를 공식 자료의 원칙에 대조했다. 아래 항목은 공개된 설계 자료에 근거한 제품 적용 판단이다. 카카오·토스 앱의 비공개 화면을 전부 조사했다거나 실사용자 인터뷰를 수행했다는 뜻은 아니다.

## 읽은 공식 자료와 적용 판단

금융 앱의 색상이나 장식을 복제하는 대신 정보의 우선순위, 행동의 예측 가능성, 안전한 취소, 읽기 쉬운 상태 표현을 이 앱에 맞게 적용했다. 인증 버튼용 수치를 모든 일반 버튼의 의무 기준으로 해석하지 않았다.

## 발견한 문제와 변경

| 영역 | 1.12에서 확인한 문제 | 1.13 동작 |
| --- | --- | --- |
| 홈 입력 | 금액을 보다가 기록하려면 포트폴리오로 이동해야 함 | 월 배당 카드에서 배당 또는 거래 입력 시작. 종목 1개는 1번, 여러 개는 종목 선택까지 2번의 탭으로 폼 진입 |
| 종목 선택 | 홈의 다른 입력에 마지막 선택 종목을 그대로 쓰면 오기록 위험 | 여러 종목은 항상 대상을 고르고, 폼 제목에서 다시 확인 |
| 저장 후 위치 | 거래 저장은 포트폴리오로 강제 이동 | 홈에서 시작한 거래는 저장 후 홈에서 합계 확인 |
| 폼 버튼 | 여러 폼이 모두 ‘저장’ 또는 ‘적용’ | 배당/거래/현재가/일정/사용 내역/보정액/분할/시각/종목의 실제 행동 명시 |
| 연속 입력 | ‘저장 후 계속’의 다음 행동이 불분명 | ‘저장 후 다음 입금’과 ‘배당 저장하기’를 구분, 기본 저장 버튼을 전체 폭으로 강조 |
| 백업 | ZIP 백업과 ZIP 복원이 같은 강조 수준 | ‘백업 파일 저장’이 주 행동, ‘백업 파일 불러오기’가 보조 행동. 확인 후 복원한다는 설명 제공 |
| 입력창 스크롤 | 고정 닫기 버튼이 스크롤된 입력칸 위에 겹침 | 제목과 닫기를 불투명한 고정 상단 영역에 배치 |
| 빈 상태 | 기록이 없다는 문구로 끝남 | 첫 입금/종목 추가의 다음 행동을 안내. 종목이 모두 보관된 상태도 추가 가능 |
| 표시 | 넓은 색상 면과 일부 다크 손익색의 낮은 가독성 | 중립 배경과 핵심 버튼의 대비, 밝은 다크 손익색, 충분한 터치 높이와 포커스 표시 |

원화/달러, 세후 금액, 미래 기록 제외, 배당 포함/제외 손익 등의 의미는 유지했다. 금융 계산식·저장 형식·클라우드 계약·네이티브 백업 동작에는 변경이 없다.

## 검증 범위

- 합성 데이터에서 단일 종목의 배당/거래 저장, 저장 후 홈 복귀, 재시작 후 일치.
- 9종목에서 명시적 저장 대상 선택, 닫기 후 포커스 복귀, 계속 작성, 미저장 폐기, 다른 종목 기록의 보존.
- 유효한 저장 기록에서 모든 종목이 보관된 상태의 종목 추가. 종목 배열 자체가 비어 있는 손상 데이터는 복구 보호가 계속 차단한다.
- 320px 및 글자 125%의 밝은/어두운 화면, 모바일·데스크톱, 폼과 선택창 스크린샷 검토.
- 기존 전체 UI 회귀, 오프라인 검토용 HTML, 31개 release QA suite와 CI 서명/네이티브/배포 검증 결과는 `RELEASE_1.13.md` 및 해당 publication 기록에 기재한다.

실기기·실계좌 수동 검증을 자동 브라우저나 에뮬레이터 결과로 대체해서 통과로 기재하지 않는다. 클릭수 감소는 구현 흐름 비교이며 사용성·전환율 향상이 측정됐다는 주장은 아니다.
